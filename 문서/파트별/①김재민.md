# ① 김재민 — 직원 관리 · 근무·급여 · 매출 · 근무자/관리자 확인

## AI에게 붙여 넣을 질문

아래 글과 함께 **이 문서**, `src/dicepos/staff` 폴더의 파일 전부, `src/dicepos/common/Session.java`, `AuthDialog.java`, `DB/dicepos_schema.sql`을 올린다.

```
나는 보드게임 카페 POS 팀 프로젝트(Java Swing + MySQL, 2학년 객체지향 수업)에서
① 직원 관리·근무/급여·매출·근무자/관리자 확인 파트를 맡았어.
첨부한 공부 문서와 코드를 보고, 교수님 앞에서 내 파트를 설명할 수 있게 가르쳐 줘.
1. 내 화면마다 버튼을 누르면 어떤 메서드가 불리고 DB에 무슨 SQL이 실행되는지 코드를 따라가며 설명해 줘.
2. 비밀번호 해시(솔트+SHA-256)와 3번 실패 30초 잠금이 코드에서 어떻게 동작하는지 설명해 줘.
3. 내 테이블을 다른 팀원이 어떻게 쓰는지, 내가 남의 테이블을 어떻게 쓰는지 설명해 줘.
4. 마지막에 교수님처럼 질문을 하나씩 내고 내 답을 채점해 줘.
코드는 고치지 말고 설명만 해 줘. 2학년이 이해할 수 있는 말로.
```

## 내 테이블

| 테이블 | 핵심 칸 | 왜 이렇게 |
|---|---|---|
| `staff` (직원) | `login_id`(UNIQUE), `password`(64자 해시), `salt`, `role`(관리자/직원), `emp_type`, `hourly_wage`/`monthly_pay`, `status`(재직/퇴사) | 비밀번호 원문은 저장하지 않는다. 퇴사해도 지우지 않아야 지난 결제·주문의 직원 기록이 남는다 |
| `work_log` (근무 기록) | `staff_id`, `work_date`, `clock_in`, `clock_out`(근무 중이면 NULL), `work_minutes`, `note` | 누적값 하나가 아니라 날마다 쌓아야 틀린 날만 고칠 수 있고, 기간 합계는 SUM으로 언제든 구한다 |
| `salary` (급여) | `staff_id` + `pay_month` UNIQUE, `base_amount`, `extra_amount`, `total_pay`, `status` | 확정한 금액을 저장해 두면 나중에 시급이 바뀌어도 지난달 급여가 안 바뀐다. UNIQUE로 같은 달 두 번 확정을 DB가 막는다 |

## 핵심 흐름 1 — 비밀번호 확인과 3번 실패 잠금 (`CheckDialog`, `PasswordUtil`)

1. 직원을 만들 때 `PasswordUtil.newSalt()`가 `SecureRandom`으로 16자리 무작위 솔트를 만든다.
2. `hash(비밀번호, 솔트)` = SHA-256(솔트 + 비밀번호) → 64자리 16진수. 이 값과 솔트만 저장한다.
3. 확인할 때 입력한 비밀번호에 저장된 솔트를 붙여 다시 해시하고, 저장된 해시와 같으면 통과.
4. 틀리면 `failCount++`. 3번이 되면 `lockedUntil = 지금 + 30초`, `javax.swing.Timer`가 1초마다 남은 시간을 보여 주고 입력칸을 끈다. `failCount`가 `static`이라 다른 팝업을 새로 열어도 같이 센다.

## 핵심 흐름 2 — 근무시간과 급여 (`WorkLogDAO.workMinutes`, `WorkSalaryPanel`)

1. 퇴근할 때 실근무 = 퇴근 − 출근 − 휴게. 4시간 이상이면 30분, 8시간 이상이면 1시간을 뺀다 (근로기준법).
2. 조회하면 그달 기록의 `work_minutes`를 더한다. 퇴근을 안 찍은 날은 빼고 빨간 글씨로 경고한다.
3. 시간제는 누적 분 × 시급 ÷ 60, 정규직·계약직은 월 기본급. 추가 수당(JSpinner)을 더해 확정한다.
4. 같은 달을 또 확정하면 DB의 UNIQUE 때문에 `SQLIntegrityConstraintViolationException`이 나고, 그걸 잡아 "이미 확정된 달" 안내를 띄운다.

## 예상 질문

1. 비밀번호를 그대로 저장하지 않는 이유와, 솔트를 쓰는 이유는?
2. 3번 틀리면 30초 잠그는 건 어느 코드가 하나요? 팝업을 닫았다 다시 열면 풀리나요?
3. 퇴사한 직원을 DELETE 하지 않는 이유는?
4. 근무시간을 날마다 저장하는 이유는? 누적 시간 하나만 저장하면 안 되나요?
5. 같은 달 급여를 두 번 확정하는 걸 어떻게 막나요?
6. 매출 관리의 일별/월별은 SQL에서 무엇이 다른가요? (`DATE_FORMAT` 형식)
7. 막대그래프는 어떻게 그렸나요? (`paintComponent`, 가장 큰 값 기준으로 높이 비율)
8. 일반 직원이 관리자 화면에 못 들어가는 이유는? 관리자 화면에서 직원 화면으로 가면 어떻게 되나요?
