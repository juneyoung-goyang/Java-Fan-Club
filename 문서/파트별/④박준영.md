## 핵심 흐름 1 — 입고 처리 트랜잭션 (`PurchaseOrderDAO.receive`)

```
con.setAutoCommit(false)
 1. 발주 상태 '요청' → '입고', receive_date  (요청이 아니면 0줄 → 예외: 두 번 입고 막기)
 2. 상세마다: 메뉴면 MenuDAO.increaseStock(con, …)   → 재고 증가, 0이었으면 품절 해제
             보드게임이면 ③ GameDAO.increaseStock(con, …) → 보유 수량 증가, 폐기였으면 정상
con.commit()  // 하나라도 실패하면 rollback
```
발주 저장(`save`)도 같은 방식: 헤더 1줄 INSERT → 생성된 `po_id`로 상세 여러 줄 INSERT → commit.

## 핵심 흐름 2 — 재고 감소와 자동 품절 (`MenuDAO.decreaseStock`)

- `UPDATE menu SET stock = stock - ? WHERE menu_id = ? AND stock >= ? AND sold_out = 0` → 바뀐 줄이 0이면 재고 부족·품절이라 예외 → ⑥의 주문 트랜잭션 전체가 rollback.
- 이어서 `stock = 0`이면 `sold_out = 1`.

## 핵심 흐름 3 — 메인 창 (`PosMainFrame`)

- 가운데 판이 `CardLayout`. `addScreen(이름, 화면, 관리자여부)`가 화면을 카드로 넣고 왼쪽에 버튼을 만든다. 6명은 화면(JPanel)만 만들고 `PosMain`에 한 줄씩 붙인다.
- 켜면 `lock()` → 메뉴 버튼이 꺼진다. 출근한 직원의 근무자 확인을 통과해야 `Session.login` → 버튼이 켜진다.
- 관리자 버튼은 관리자 확인 → `Session.unlockAdmin`. 직원 화면으로 돌아가면 `lockAdmin()`으로 다시 잠긴다.
