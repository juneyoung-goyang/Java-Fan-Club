다이스 POS를 **각자 설명하기 위해** 알아야 할 개념을 가장 작은 단위부터 순서대로 정리했다.
아래 단계를 알아야 위 단계를 설명할 수 있으므로 1단계부터 차례로 읽는다.
예시는 모두 계획서의 결제 예시(Room 19, 김민수 회원 2명, 오렌지주스 2잔 + 라면 1개, 24,500원)를 쓴다.

```
7. Swing      화면 부품 → 판 → 배치 → 이벤트 → 화면 전환 → Timer
6. Java       클래스·객체 → DTO·DAO → 3층 구조 → 예외처리
5. 동시성      두 곳에서 동시에 → 행 잠금(FOR UPDATE) → UNIQUE
4. JDBC       Connection → PreparedStatement → ResultSet → 트랜잭션
3. SQL        SQL 문 하나 → 트랜잭션(여러 SQL을 한 덩어리로)
2. 관계        PK → FK → 1:N(헤더 + 상세) → 제약조건
1. 데이터      필드 → 타입 → 행 → 테이블
```

> 코드는 이해를 돕기 위한 예시다. 실제 클래스·메서드 이름은 01 공통 개발 가이드와 개인 개발 문서를 따른다.

## 1단계 · 데이터 한 칸부터 테이블까지

### 1. 필드 (열, column)
정보 한 칸. 예: `total_amount`(총 결제 금액), `card_amount`(카드 결제 금액)

### 2. 데이터 타입
칸에 들어갈 값의 종류.

| 타입 | 뜻 | 예 |
|---|---|---|
| `INT` | 정수 | 24500 |
| `VARCHAR(20)` | 글자 (최대 20자) | '김민수' |
| `DATETIME` | 날짜 + 시각 | 2026-11-03 21:20:41 |
| `TINYINT` | 0 / 1 | cafe_table.is_active (1 사용가능 / 0 사용불가) |

### 3. 행 (레코드, row)
데이터 한 건. **결제 1건 = payment 1줄**, 회원 1명 = member 1줄.

### 4. 테이블
같은 종류의 행을 모은 것. 결제들 → `payment`, 회원들 → `member`. 다이스 POS는 테이블 17개.

## 2단계 · 행과 행을 잇기

### 5. 기본키 (PK, Primary Key)
행마다 붙는 겹치지 않는 번호. `AUTO_INCREMENT`면 DB가 1씩 늘려 자동으로 붙인다. 예: `pay_id = 1042`

### 6. 외래키 (FK, Foreign Key)
다른 테이블의 행을 가리키는 번호. 예: `payment.member_id = 7` → member 테이블 7번 = 김민수.

### 7. 1:N 관계 (헤더 + 상세)
한 건(1)에 여러 줄(N)이 딸린 구조. 교수님 피드백의 핵심이다.

**payment** (결제 1건 = 1줄)

| pay_id (PK) | usage_id | member_id | total_amount | card_amount | cash_amount | point_amount |
|---|---|---|---|---|---|---|
| 1042 | 315 | 7 | 24500 | 20000 | 2500 | 2000 |

**payment_detail** (결제한 항목마다 1줄)

| pay_detail_id (PK) | pay_id (FK) | item_type | menu_id | qty | unit_price | subtotal |
|---|---|---|---|---|---|---|
| 5120 | 1042 | 이용료 | NULL | 2 | 7000 | 14000 |
| 5121 | 1042 | 메뉴 | 12 (오렌지주스) | 2 | 3000 | 6000 |
| 5122 | 1042 | 메뉴 | 7 (라면) | 1 | 4500 | 4500 |

결제·주문·발주 모두 같은 모양이다: `payment` + `payment_detail`, `orders` + `order_detail`, `purchase_order` + `purchase_order_detail`.

### 8. 제약조건
DB가 직접 막아 주는 규칙.

| 제약 | 뜻 | 다이스 POS 예 |
|---|---|---|
| `NOT NULL` | 빈칸 금지 | 결제 일시 |
| `UNIQUE` | 같은 값 중복 금지 | `payment.usage_id` → 같은 이용 건 두 번 결제 불가, `staff.login_id` |
| `DEFAULT` | 안 넣으면 들어가는 기본값 | 추가 수당 기본값 0 |

**확인 질문**: 주스 2개와 라면 1개를 결제하면 각 테이블에 몇 줄이 생기나? / 결제를 한 테이블에만 저장하면 무엇이 문제인가?

## 3단계 · DB에 일 시키기

### 9. SQL 문 하나 = DB에 시키는 일 하나

| SQL | 하는 일 | 예 |
|---|---|---|
| `INSERT` | 행 추가 | 결제 1줄 저장 |
| `SELECT` | 행 조회 | 오늘 결제 목록 보기 (`WHERE`, `JOIN`, `GROUP BY`, `SUM`) |
| `UPDATE` | 값 수정 | 포인트 2,000점 차감 |
| `DELETE` | 행 삭제 | 대부분 쓰지 않고 상태 변경으로 대신 (퇴사, 폐기, 사용불가, 취소) |

> 삭제 대신 상태를 바꾸는 이유: 다른 테이블이 FK로 그 행을 가리키고 있어서(예: 퇴사한 직원이 처리한 결제), 지우면 기록이 깨진다.

### 10. 트랜잭션 — 여러 SQL을 "전부 성공 아니면 전부 취소"로 묶은 한 덩어리
[결제하기] 버튼 한 번에 SQL 6개가 실행된다.

1. `payment` 1줄 INSERT
2. `payment_detail` 3줄 INSERT
3. `member` 포인트 UPDATE
4. `table_usage` 상태를 '결제완료'로 UPDATE

4번에서 오류가 나면? 돈은 받았는데 룸은 '이용중'으로 남는다. 그래서 묶는다.

- 전부 성공 → `commit` (한꺼번에 확정)
- 하나라도 실패 → `rollback` (1번부터 전부 없던 일로)

이 "쪼갤 수 없는 한 덩어리" 성질을 **원자성**이라고 한다.

**확인 질문**: 트랜잭션을 쓰지 않으면 결제 중 오류가 났을 때 어떤 상태가 남나?

## 4단계 · JDBC — Java에서 DB에 일 시키기

### 11. 드라이버 (MySQL Connector/J)
Java와 MySQL 사이의 통역 라이브러리(jar). Eclipse 프로젝트의 Build Path에 한 번 추가한다.

### 12. Connection
Java ↔ DB를 잇는 통로 1개. `DriverManager.getConnection(주소, 아이디, 비밀번호)`로 열고, 다이스 POS에서는 `DBUtil.getConnection()`(④)이 대신 연다.

### 13. PreparedStatement
SQL을 담는 그릇. 값 자리는 `?`로 비워 두고 나중에 채운다.

```java
String sql = "SELECT * FROM staff WHERE login_id = ?";
PreparedStatement ps = con.prepareStatement(sql);
ps.setString(1, inputId);   // 첫 번째 ? 에 값 넣기
```

`?`를 쓰는 이유 — 문자열을 이어 붙이면 아이디 칸에 `' OR '1'='1`을 넣었을 때 조건이 항상 참이 되어 아무나 통과한다(**SQL 인젝션**).

### 14. 실행 두 가지

| 메서드 | 쓰는 SQL | 돌려받는 것 |
|---|---|---|
| `executeQuery()` | SELECT | `ResultSet` (결과 표) |
| `executeUpdate()` | INSERT·UPDATE·DELETE | 바뀐 행 수 (`int`) |

### 15. ResultSet
SELECT 결과 표를 한 줄씩 읽는 손가락.

```java
ResultSet rs = ps.executeQuery();
while (rs.next()) {                       // 다음 줄로 이동, 없으면 false
    String name = rs.getString("name");
    int point = rs.getInt("point");
}
```

### 16. 자동 생성 키
payment를 INSERT하면 DB가 `pay_id = 1042`를 만든다. 상세 3줄에 1042를 넣어야 하므로 그 번호를 돌려받는다.

```java
PreparedStatement ps = con.prepareStatement(sql, Statement.RETURN_GENERATED_KEYS);
ps.executeUpdate();
ResultSet keys = ps.getGeneratedKeys();
keys.next();
int payId = keys.getInt(1);   // 1042
```

### 17. try-with-resources
다 쓴 `PreparedStatement`·`ResultSet`·`Connection`을 자동으로 닫는다. 안 닫으면 통로가 쌓여 DB가 막힌다.

```java
try (PreparedStatement ps = con.prepareStatement(sql)) {
    ...
}   // 여기서 ps.close() 자동 호출
```

### 18. JDBC 트랜잭션
- 기본값 `autoCommit = true` → SQL 하나마다 바로 확정된다.
- `setAutoCommit(false)`로 끄면 `commit()`/`rollback()` 할 때까지 한 덩어리.
- 트랜잭션은 **Connection 하나에 묶인다.** 그래서 다른 팀원의 DAO 메서드를 부를 때 **같은 `con`을 넘긴다**.

```java
Connection con = null;
try {
    con = DBUtil.getConnection();
    con.setAutoCommit(false);                          // 묶기 시작
    int payId = paymentDAO.insert(con, payment);       // 1042 받음
    for (PaymentDetailDTO d : details)
        paymentDetailDAO.insert(con, payId, d);        // 상세 3줄
    memberDAO.updatePoint(con, 7, -2000);              // 포인트 차감
    tableUsageDAO.finish(con, usageId);                // ⑤의 메서드, 같은 con
    con.commit();                                      // 전부 확정
} catch (SQLException e) {
    if (con != null) try { con.rollback(); } catch (SQLException ignore) {}   // 전부 취소
    JOptionPane.showMessageDialog(this, "결제 중 오류가 발생해 취소되었습니다.");
} finally {
    if (con != null) try { con.close(); } catch (SQLException ignore) {}
}
```

**확인 질문**: `?`를 쓰는 이유는? / 다른 팀원 메서드에 왜 Connection을 넘기나?

## 5단계 · 동시성 — 두 곳에서 동시에 할 때

### 19. 문제 상황
'스플렌더'가 1개 남았을 때 Room 19 키오스크와 카운터 POS에서 거의 동시에 [대여]를 누르면:

| 순서 | 키오스크 | POS |
|---|---|---|
| 1 | 대여 가능 수량 읽기 → 1 | |
| 2 | | 대여 가능 수량 읽기 → 1 |
| 3 | 대여 INSERT | |
| 4 | | 대여 INSERT → **1개를 두 번 대여** |

### 20. 해결 — `SELECT … FOR UPDATE` (행 잠금)
트랜잭션 안에서 읽으면서 그 행을 잠근다. 다른 쪽은 앞 트랜잭션이 끝날 때(commit/rollback)까지 기다린다.

```sql
SELECT stock FROM game WHERE game_id = ? FOR UPDATE;
SELECT COUNT(*) FROM game_rental WHERE game_id = ? AND status = '대여중';
-- 대여 가능 수량 = stock − 대여중 수
```

| 순서 | 키오스크 | POS |
|---|---|---|
| 1 | 읽으면서 잠금 → 1 | |
| 2 | | 읽으려다 **기다림** |
| 3 | 대여 INSERT → commit (잠금 풀림) | |
| 4 | | 읽음 → 0 → rollback, "예약하시겠어요?" 안내 |

같은 방법으로 ⑤ 이용 시작에서 한 룸을 두 번 입장 처리하는 것도 막는다.

### 21. 마지막 방어선 — UNIQUE
코드가 실수해도 DB가 막는다. `payment.usage_id`의 UNIQUE → 같은 이용 건을 두 번 결제하면 DB가 오류를 낸다.

**확인 질문**: FOR UPDATE는 언제 잠금이 풀리나? / UNIQUE와 FOR UPDATE는 각각 무엇을 막나?

## 6단계 · Java (객체지향)

### 22. 변수와 타입
값 하나를 담는 상자. `int`(24500), `String`("김민수"), `boolean`(true/false), `LocalDateTime`(2026-11-03 21:20 — ⑤ 이용 시간 계산).

### 23. 클래스와 객체
클래스 = **설계도**, 객체 = 설계도로 **실제로 만든 것**.

```java
MemberDTO m = new MemberDTO();   // MemberDTO 설계도로 객체 하나 생성
```

### 24. 필드와 메서드
필드 = 객체가 가진 값(이름, 포인트), 메서드 = 객체가 하는 일(포인트 차감).

### 25. 캡슐화 (private + getter/setter)
필드를 숨기고 메서드로만 바꾸게 해서 이상한 값을 막는다.

```java
private int point;
public int getPoint() { return point; }
public void setPoint(int p) {
    if (p < 0) throw new IllegalArgumentException("포인트는 0 이상");
    point = p;
}
```

### 26. DTO — DB 1줄을 담는 객체

| DB | Java |
|---|---|
| member 테이블 | `MemberDTO` 클래스 |
| 김민수 1줄 | `MemberDTO` 객체 1개 |
| 열(필드) | 필드(변수) |

### 27. DAO — 한 테이블의 SQL을 모아 둔 클래스
예: `MemberDAO` = `insert()`, `search()`, `update()`, `updatePoint()`.
**테이블 담당자 = 그 DAO를 만드는 사람.** "담당자가 만든 메서드를 부른다" = 그 사람의 DAO 메서드를 부른다.

### 28. 3층 구조 — 화면 → DAO → DB

```
[MemberPanel 화면] ──검색어──▶ [MemberDAO] ──SQL──▶ [MySQL]
        ▲                          │
        └──── List<MemberDTO> ─────┘
```

```java
// 화면 (②)
List<MemberDTO> list = memberDAO.search(tfSearch.getText().trim());
// DAO (②)
while (rs.next()) list.add(new MemberDTO(rs.getInt("member_id"), rs.getString("name"), ...));
```

화면은 SQL을 모르고, DAO는 화면을 모른다 → 한쪽을 고쳐도 다른 쪽이 덜 흔들린다.

### 29. 컬렉션 (ArrayList)
객체 여러 개를 담는 목록. 조회 결과 `List<MemberDTO>`, ⑥ 장바구니 `List<CartItem>`.
장바구니는 [주문하기] 전까지 DB가 아니라 메모리(ArrayList)에만 둔다.

### 30. static — 객체 없이 바로 쓰는 것
프로그램 전체에 하나면 되는 것: `DBUtil.getConnection()`(④), `FeeCalculator`(⑤), `Session`의 현재 근무자(①).

### 31. 상속과 인터페이스
- 상속: `class MemberPanel extends JPanel` = JPanel이 할 줄 아는 건 다 하고 내 화면을 더한다.
- 인터페이스: `implements ActionListener` = 버튼이 눌리면 부를 `actionPerformed()`를 만들겠다는 약속.

### 32. 예외처리
실행 중 문제를 잡아 프로그램이 죽지 않게 한다.

| 상황 | 예외 / 처리 | 안내 |
|---|---|---|
| DB 오류 | `SQLException` | "저장 중 오류가 발생했습니다." |
| 숫자 칸에 글자 | `NumberFormatException` | "수량은 숫자로 입력하세요." |
| 빈칸·음수 | 직접 `if`로 검사 | "이름을 입력하세요." |

DAO는 `throws SQLException`으로 위로 넘기고, **화면이 `try-catch`로 잡아 안내창**을 띄운다(DAO는 화면을 모르므로).

## 7단계 · Swing — 화면 만들기

### 33. 컴포넌트 — 화면 부품 하나

| 부품 | 쓰는 곳 |
|---|---|
| `JLabel` | 제목, "총 결제 금액 24,500원" |
| `JButton` | [저장], [결제하기] |
| `JTextField` | 이름, 수량 입력 |
| `JPasswordField` | 비밀번호 (●로 표시) |
| `JComboBox` | 분류, 결제 수단 고르기 |
| `JRadioButton` + `ButtonGroup` | 사용가능 / 사용불가 (하나만 선택) |
| `JCheckBox` | 품절 |
| `JTable` | 목록 표 |

### 34. 컨테이너 — 부품을 담는 판
- `JFrame`: 창. POS 창(`PosMainFrame`), 키오스크 창(`KioskFrame`)
- `JPanel`: 창 안의 판. 팀원 화면 하나하나가 JPanel(`MemberPanel`, `MenuPanel` …)
- `JDialog`: 팝업 창. 결제 팝업(`PaymentDialog`), 관리자 확인. **modal**이면 닫기 전까지 뒤 화면을 못 누른다.
- `JScrollPane`: 표가 길 때 스크롤. `new JScrollPane(table)`

### 35. 배치관리자 — 판 안에 부품을 놓는 규칙

| 배치관리자 | 놓는 방식 | 다이스 POS 예 |
|---|---|---|
| `BorderLayout` | 동·서·남·북·가운데 | POS 메인 창: 왼쪽 메뉴(WEST) + 가운데 화면(CENTER) |
| `GridLayout` | 같은 크기 격자 | 테이블 현황 룸 카드, 키오스크 메뉴 버튼 |
| `FlowLayout` | 한 줄로 차례대로 | 검색 줄 (입력칸 + [검색]) |
| `CardLayout` | 여러 장 중 한 장만 보이기 | 화면 전환 |

판 안에 판을 넣어 섞어 쓴다(예: BorderLayout의 NORTH에 FlowLayout 검색 줄).

### 36. JTable + DefaultTableModel
표 = 보이는 것(`JTable`) + 데이터(`DefaultTableModel`). 데이터만 바꾸면 표가 따라 바뀐다.

```java
DefaultTableModel model = new DefaultTableModel(new String[]{"번호", "이름", "포인트"}, 0);
JTable table = new JTable(model);
add(new JScrollPane(table), BorderLayout.CENTER);

model.setRowCount(0);                                  // 기존 줄 지우기
for (MemberDTO m : list)
    model.addRow(new Object[]{ m.getMemberId(), m.getName(), m.getPoint() });

int row = table.getSelectedRow();                      // 선택한 줄 (-1이면 선택 없음)
int id = (int) model.getValueAt(row, 0);
```

### 37. 이벤트 — 사용자 행동 → 리스너 메서드 호출
- **이벤트 소스**: 이벤트가 생기는 부품 (버튼)
- **리스너**: 그때 실행할 코드 (`ActionListener`)
- **등록**: 둘을 연결 (`addActionListener`)

| 리스너 | 언제 | 예 |
|---|---|---|
| `ActionListener` | 버튼 클릭, 입력칸에서 Enter | [저장], [결제하기] |
| `MouseListener` | 클릭·더블클릭·마우스 올림 | 룸 카드 클릭, 게임 카드 테두리 |
| `ListSelectionListener` | 표의 줄 선택 | 결제 목록 줄 → 오른쪽에 상세 |
| `WindowListener` | 창 닫기 | "종료하시겠습니까?" |

**버튼 하나가 1~6단계를 모두 지나간다** — ④ 메뉴 관리 [저장]:

```java
btnSave.addActionListener(e -> {                                 // 7단계: 이벤트
    String name = tfName.getText().trim();
    if (name.isEmpty()) {                                        // 6단계: 입력 검사
        JOptionPane.showMessageDialog(this, "메뉴 이름을 입력하세요.");
        return;
    }
    int price;
    try {
        price = Integer.parseInt(tfPrice.getText().trim());
    } catch (NumberFormatException ex) {                         // 6단계: 예외처리
        JOptionPane.showMessageDialog(this, "가격은 숫자로 입력하세요.");
        return;
    }
    try {
        menuDAO.insert(new MenuDTO(name, (String) cbCategory.getSelectedItem(), price));  // 6단계: DTO → DAO
        JOptionPane.showMessageDialog(this, "저장했습니다.");                               // 4단계: JDBC INSERT
        refreshTable();                                                                     // 3단계: SELECT
    } catch (SQLException ex) {
        JOptionPane.showMessageDialog(this, "저장 중 오류가 발생했습니다.");
    }
});
```

### 38. 안내창과 팝업
- `JOptionPane.showMessageDialog`: 알림 ("저장했습니다.")
- `JOptionPane.showConfirmDialog`: 예/아니요 ("정말 삭제하시겠습니까?")
- `JDialog` (modal): 입력이 많은 팝업 — 결제 팝업, 관리자 확인

### 39. 화면 전환 — CardLayout
6명이 만든 JPanel을 **한 창에 합치는 방법**이다. POS 메인 창(④)의 가운데 판에 이름을 붙여 넣고, 왼쪽 메뉴를 누르면 그 이름의 화면을 보여 준다. 키오스크(③)도 같은 방식.

```java
CardLayout cards = new CardLayout();
JPanel center = new JPanel(cards);
center.add(new MemberPanel(), "회원 관리");      // ②의 화면
center.add(new MenuPanel(), "메뉴 관리");        // ④의 화면
btnMember.addActionListener(e -> cards.show(center, "회원 관리"));
```

### 40. Timer와 스레드
- Swing 화면은 **이벤트 처리 스레드(EDT)** 한 줄이 그린다. 여기서 오래 걸리는 일을 하면 화면이 멈춘다.
- `javax.swing.Timer`: 정해진 간격마다 EDT에서 코드를 실행 → 화면을 바로 바꿔도 안전.

  ```java
  new javax.swing.Timer(1000, e -> refreshElapsed()).start();   // 1초마다 경과 시간 갱신
  ```

  쓰는 곳: 3회 실패 30초 잠금 카운트다운(①), 대여 현황 5초 갱신(③), 룸 경과 시간(⑤), 키오스크 주문 확인(⑥)
- 다른 스레드에서 화면을 바꿀 때는 `SwingUtilities.invokeLater(() -> label.setText(...));` 로 EDT에 맡긴다.

**확인 질문**: 6명의 화면을 한 창에 어떻게 합쳤나? / Timer로 화면을 갱신해도 안전한 이유는?
