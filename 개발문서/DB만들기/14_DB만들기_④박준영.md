# DB 만들기 — ④ 박준영 (메뉴 관리 · 발주 관리 · 공통 뼈대)

내 테이블 3개를 **직접 만들고, 데이터를 넣고, 화면 기능에 쓸 SQL을 미리 실행해 보는** 순서다.
여기 있는 SQL은 모두 실제로 실행해서 결과를 확인했다. 기초 개념은 [04 기초 개념 정리](../04_기초개념정리.md)를 본다.

---

## 0. 한눈에

| 구분 | 테이블 | 하는 일 |
|---|---|---|
| **내 테이블** | `menu` | 메뉴 이름·분류·판매가·재고·품절 |
| | `purchase_order` | 발주 1건 (헤더): 누가, 어디에, 언제, 총액, 상태 |
| | `purchase_order_detail` | 발주한 품목마다 1줄 (상세): 메뉴 또는 보드게임, 수량, 단가, 금액 |
| 내가 참조 | `staff` (①) | 발주한 직원 번호·이름 조회 |
| | `game` (③) | 보드게임 번호·이름 조회, 입고 시 재고 증가는 **③의 메서드로** |
| 나를 참조 | `order_detail` (⑥), `payment_detail` (②) | 메뉴 번호를 가리킴 → 메뉴 삭제에 영향 |

```
staff(①) 1 ──< N purchase_order 1 ──< N purchase_order_detail N >── 1 menu
                                                             N >── 1 game(③)
```

## 1. 준비 (한 번만)

### 1-1. 설치 확인
- MySQL Community Server 8.0 + MySQL Workbench 8.0 (설치할 때 정한 root 비밀번호 기억)
- Eclipse + JDK 17, `mysql-connector-j` jar

### 1-2. 팀 DB 한 번에 만들기
1. Workbench에서 `Local instance` 접속
2. `File → Open SQL Script` → [`개발문서/dicepos_schema.sql`](../dicepos_schema.sql)
3. 번개 아이콘(전체 실행) 클릭
4. 왼쪽 `SCHEMAS`에서 새로고침 → `dicepos` 안에 테이블 **17개**

> ⚠️ 이 파일은 맨 위에서 `DROP DATABASE IF EXISTS dicepos`를 실행한다. **다시 실행하면 넣어 둔 데이터가 모두 지워지고 처음 상태로 돌아간다.** (꼬였을 때 초기화 용도로 쓰면 된다.)

### 1-3. (제안) 프로젝트 전용 DB 계정
root 비밀번호는 사람마다 달라서 `DBUtil`에 적으면 GitHub에 올라가고 팀원마다 고쳐야 한다. 전용 계정을 만들면 6명이 같은 `DBUtil`을 그대로 쓴다. **각자 자기 컴퓨터에서 root로 한 번 실행:**

```sql
CREATE USER 'dicepos'@'localhost' IDENTIFIED BY 'dice1234';
GRANT ALL PRIVILEGES ON dicepos.* TO 'dicepos'@'localhost';
```

> `DBUtil`은 ④ 담당이라 팀에 이 방식을 제안하고 정한다. (9번 참고)

## 2. 만드는 순서 — 참조당하는 테이블이 먼저

FK는 **이미 있는 테이블**만 가리킬 수 있다. 그래서 순서가 정해진다.

```
staff(①), game(③)  →  menu  →  purchase_order  →  purchase_order_detail
(남의 테이블, 먼저)      (나)      (staff를 가리킴)    (purchase_order·menu·game을 가리킴)
```

순서를 틀려 `purchase_order`를 `staff`보다 먼저 만들면 오류가 난다.
`ERROR 1824 … Failed to open the referenced table 'staff'` (MariaDB는 `ERROR 1005 … errno: 150`)

지울 때는 **반대 순서** (상세 → 헤더 → 메뉴).

### 연습 — 빈 DB에 내 테이블 직접 만들어 보기
팀 DB(`dicepos`)는 건드리지 않고 연습용 DB에서 한다.

```sql
CREATE DATABASE dicepos_practice DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
USE dicepos_practice;
-- ① dicepos_schema.sql에서 CREATE TABLE staff (...) 와 CREATE TABLE game (...) 부분을 복사해 실행
-- ② 아래 3번의 내 테이블 3개를 순서대로 직접 입력해 실행
-- ③ 끝나면 정리
DROP DATABASE dicepos_practice;
```

## 3. 내 테이블 한 줄씩 이해하기

> 공통 스크립트에는 각 줄에 `COMMENT '설명'`이 붙어 있다. 여기서는 읽기 쉽게 빼고 구조만 같게 적었다.

### 3-1. menu (메뉴)

```sql
CREATE TABLE menu (
  menu_id   INT          NOT NULL AUTO_INCREMENT,
  name      VARCHAR(30)  NOT NULL,
  category  VARCHAR(10)  NOT NULL,
  price     INT          NOT NULL,
  stock     INT          NOT NULL DEFAULT 0,
  sold_out  TINYINT(1)   NOT NULL DEFAULT 0,
  PRIMARY KEY (menu_id),
  UNIQUE (name)
);
```

| 줄 | 뜻 | 이렇게 한 이유 |
|---|---|---|
| `menu_id … AUTO_INCREMENT` + `PRIMARY KEY` | 메뉴 번호, 자동 증가 | 이름은 바뀔 수 있으니 번호로 구별 |
| `name VARCHAR(30)` + `UNIQUE (name)` | 메뉴 이름, 중복 금지 | 같은 이름 메뉴 2개면 주문·발주 때 헷갈림 → 중복이면 `1062` 오류 |
| `category VARCHAR(10)` | 음료 / 간식 / 식사 | ⑥ 키오스크·주문 화면의 분류 탭 |
| `price INT` | **판매** 가격 | 원 단위라 소수가 없음 → `INT` |
| `stock INT … DEFAULT 0` | 재고 | 안 넣으면 0. 입고(나)하면 늘고, 주문(⑥)하면 줄어듦 |
| `sold_out TINYINT(1) … DEFAULT 0` | 품절 (1 = 주문 불가) | 재고가 0이 되면 1, 입고하면 0. 재료가 떨어졌을 때 직원이 직접 체크도 가능 |

### 3-2. purchase_order (발주 — 헤더)

```sql
CREATE TABLE purchase_order (
  po_id         INT          NOT NULL AUTO_INCREMENT,
  staff_id      INT,
  supplier      VARCHAR(30),
  order_date    DATETIME     NOT NULL,
  total_amount  INT          NOT NULL DEFAULT 0,
  status        VARCHAR(10)  NOT NULL DEFAULT '요청',
  receive_date  DATETIME,
  PRIMARY KEY (po_id),
  FOREIGN KEY (staff_id) REFERENCES staff(staff_id) ON DELETE SET NULL
);
```

| 줄 | 뜻 | 이렇게 한 이유 |
|---|---|---|
| `po_id` | 발주 번호 | 상세가 이 번호로 헤더를 가리킴 |
| `staff_id INT` (NULL 허용) + `ON DELETE SET NULL` | 발주한 직원 (①의 staff) | 직원 행이 지워져도 발주 기록은 남기고 직원 칸만 비움 |
| `supplier VARCHAR(30)` (NULL 허용) | 거래처 | 선택 입력 |
| `order_date DATETIME NOT NULL` | 발주 일시 | 목록 정렬, 직전 단가 찾기 |
| `total_amount INT … DEFAULT 0` | 총 발주 금액 = 상세 `amount`의 합 | 목록에서 매번 SUM 하지 않도록 **요약을 헤더에** 저장 |
| `status … DEFAULT '요청'` | 요청 → 입고, 요청 → 취소 | 취소해도 **지우지 않고 상태만** 바꿔 기록을 남김 |
| `receive_date DATETIME` (NULL 허용) | 입고 일시 | 입고 전이면 NULL |

### 3-3. purchase_order_detail (발주 상세)

```sql
CREATE TABLE purchase_order_detail (
  po_detail_id  INT          NOT NULL AUTO_INCREMENT,
  po_id         INT          NOT NULL,
  item_type     VARCHAR(10)  NOT NULL,
  menu_id       INT,
  game_id       INT,
  qty           INT          NOT NULL,
  unit_cost     INT          NOT NULL,
  amount        INT          NOT NULL,
  PRIMARY KEY (po_detail_id),
  FOREIGN KEY (po_id)   REFERENCES purchase_order(po_id) ON DELETE CASCADE,
  FOREIGN KEY (menu_id) REFERENCES menu(menu_id),
  FOREIGN KEY (game_id) REFERENCES game(game_id)
);
```

| 줄 | 뜻 | 이렇게 한 이유 |
|---|---|---|
| `po_id NOT NULL` + `ON DELETE CASCADE` | 어느 발주의 상세인지 | 헤더 없는 상세는 의미가 없음 → 헤더가 지워지면 같이 지워짐 (우리는 헤더를 지우지 않지만 안전장치) |
| `item_type VARCHAR(10)` | '메뉴' / '보드게임' | 교수님 피드백: 보드게임도 발주 |
| `menu_id INT` / `game_id INT` (둘 다 NULL 허용) | 발주한 메뉴 / 보드게임 | **둘 중 하나만 채운다.** DB가 이 규칙을 막아 주지 않으므로 저장 전에 Java에서 검사 + 7번 검사 SQL |
| `qty INT` | 발주 수량 | |
| `unit_cost INT` | **매입** 단가 (그때 값) | 교수님 피드백: 단가. 단가는 발주마다 바뀌므로 그때 값을 남겨야 지난 발주 금액이 안 바뀜. `menu.price`(판매가)와 다르다 |
| `amount INT` | `qty × unit_cost` | Java에서 계산해 저장 |

## 4. 예시 데이터 넣기 (발주 3건)

팀 DB(`dicepos`)에서 실행한다. 공통 스크립트의 예시 데이터 기준 번호: 직원 1 김지우(관리자) · 2 박민서 / 메뉴 2 오렌지주스 · 5 츄러스(품절) · 6 라면 / 게임 1 스플렌더 · 6 카탄.

```sql
USE dicepos;

-- 발주 1: 식자재 (오렌지주스 20 + 츄러스 30) = 69,000원
START TRANSACTION;
INSERT INTO purchase_order (staff_id, supplier, order_date, total_amount, status)
VALUES (1, '바른식자재', '2026-11-10 10:30:00', 69000, '요청');
SET @po = LAST_INSERT_ID();          -- 방금 생긴 po_id (Java의 getGeneratedKeys와 같은 역할)
INSERT INTO purchase_order_detail (po_id, item_type, menu_id, game_id, qty, unit_cost, amount) VALUES
 (@po, '메뉴', 2, NULL, 20, 1200, 24000),
 (@po, '메뉴', 5, NULL, 30, 1500, 45000);
COMMIT;

-- 발주 2: 보드게임 (카탄 1 + 스플렌더 1) = 70,000원
START TRANSACTION;
INSERT INTO purchase_order (staff_id, supplier, order_date, total_amount, status)
VALUES (1, '주사위게임유통', '2026-11-10 10:40:00', 70000, '요청');
SET @po = LAST_INSERT_ID();
INSERT INTO purchase_order_detail (po_id, item_type, menu_id, game_id, qty, unit_cost, amount) VALUES
 (@po, '보드게임', NULL, 6, 1, 38000, 38000),
 (@po, '보드게임', NULL, 1, 1, 32000, 32000);
COMMIT;

-- 발주 3: 라면 10 = 20,000원 (나중에 취소해 볼 것)
START TRANSACTION;
INSERT INTO purchase_order (staff_id, supplier, order_date, total_amount, status)
VALUES (2, '바른식자재', '2026-11-10 11:00:00', 20000, '요청');
SET @po = LAST_INSERT_ID();
INSERT INTO purchase_order_detail (po_id, item_type, menu_id, game_id, qty, unit_cost, amount) VALUES
 (@po, '메뉴', 6, NULL, 10, 2000, 20000);
COMMIT;
```

## 5. 기능별 SQL — DAO에 들어갈 것

Java(DAO)에서는 값 자리를 `?`로 두고 `PreparedStatement`로 채운다. Workbench에서 연습할 때는 `?` 대신 실제 값을 넣는다.

### 5-1. 메뉴 관리 (`MenuDAO`)

| 기능 | SQL | Java에서 |
|---|---|---|
| 분류별 목록 `findByCategory` | `SELECT * FROM menu WHERE category = ? ORDER BY name` | ResultSet → `List<MenuDTO>` (⑥도 사용) |
| 전체 목록 | `SELECT * FROM menu ORDER BY category, name` | 표 새로고침 |
| [추가] | `INSERT INTO menu (name, category, price, stock) VALUES (?, ?, ?, ?)` | `1062`면 "이미 있는 메뉴 이름입니다." |
| [수정] | `UPDATE menu SET name = ?, category = ?, price = ?, stock = ?, sold_out = ? WHERE menu_id = ?` | |
| 품절 체크 | `UPDATE menu SET sold_out = ? WHERE menu_id = ?` | 체크박스 값 1 / 0 |
| [삭제] 전 확인 | 아래 SQL — 결과가 0일 때만 삭제 | 0이 아니면 "주문·결제·발주 기록이 있는 메뉴는 삭제할 수 없습니다. 품절로 바꿔 주세요." |
| [삭제] | `DELETE FROM menu WHERE menu_id = ?` | |

```sql
-- 이 메뉴를 가리키는 기록 수 (⑥ 주문 상세 + ② 결제 상세 + 내 발주 상세)
SELECT (SELECT COUNT(*) FROM order_detail          WHERE menu_id = ?)
     + (SELECT COUNT(*) FROM payment_detail        WHERE menu_id = ?)
     + (SELECT COUNT(*) FROM purchase_order_detail WHERE menu_id = ?) AS used_count;
```

> 개인 개발 문서에는 ⑥의 `OrderDAO.hasMenuOrder()`만 확인한다고 적혀 있지만, `payment_detail`(②)과 내 `purchase_order_detail`도 menu를 FK로 가리킨다. 하나라도 있으면 `DELETE`가 `1451` 오류로 막히므로 **세 곳 모두** 확인한다.

### 5-2. ⑥에게 주는 재고 메서드
⑥의 주문 트랜잭션 안에서 **같은 Connection으로** 불린다.

| 메서드 | SQL | 설명 |
|---|---|---|
| `decreaseStock(con, menuId, qty)` | `UPDATE menu SET stock = stock - ? WHERE menu_id = ? AND stock >= ?` | `executeUpdate()`가 **0을 돌려주면 재고 부족** → 예외를 던져 ⑥이 rollback |
| (이어서) | `UPDATE menu SET sold_out = 1 WHERE menu_id = ? AND stock = 0` | 재고가 0이 되면 자동 품절 |
| `increaseStock(con, menuId, qty)` | `UPDATE menu SET stock = stock + ?, sold_out = 0 WHERE menu_id = ?` | 입고(나), 주문 취소(⑥) |

`AND stock >= ?`를 붙이는 이유: 재고를 읽고 → 빼는 두 단계로 나누면 그 사이에 다른 주문이 끼어들 수 있다. 조건을 붙인 `UPDATE` 한 번은 DB가 한 번에 처리하므로 재고가 음수가 되지 않는다.

```sql
-- 연습: 라면(6) 재고 15에서
UPDATE menu SET stock = stock - 2  WHERE menu_id = 6 AND stock >= 2;    -- 1 row affected → 13
UPDATE menu SET stock = stock - 99 WHERE menu_id = 6 AND stock >= 99;   -- 0 rows affected → 재고 부족
```

### 5-3. 발주 관리 (`PurchaseOrderDAO`)

**[발주 요청] — 헤더 + 상세 트랜잭션** (4번 예시와 같은 모양)

```
autoCommit 끄기
 → purchase_order INSERT (status '요청', total_amount = 상세 금액 합) → 생성된 po_id 받기
 → 품목마다 purchase_order_detail INSERT (메뉴면 menu_id, 보드게임이면 game_id)
 → commit  /  실패하면 rollback (품목 없는 빈 발주가 남지 않게)
```

**발주 내역 (상태 필터)**

```sql
SELECT p.po_id, p.order_date, p.supplier, s.name AS staff_name,
       COUNT(d.po_detail_id) AS item_count, p.total_amount, p.status
FROM purchase_order p
LEFT JOIN staff s                 ON p.staff_id = s.staff_id
LEFT JOIN purchase_order_detail d ON d.po_id = p.po_id
WHERE p.status = ?                          -- '전체'를 고르면 이 줄을 빼고 실행
GROUP BY p.po_id, p.order_date, p.supplier, s.name, p.total_amount, p.status
ORDER BY p.order_date DESC;
```

`LEFT JOIN`인 이유: 직원 칸이 NULL(직원 삭제)이어도 발주는 목록에 나와야 한다.

**발주 상세 (선택한 발주의 품목)**

```sql
SELECT d.po_detail_id, d.item_type, COALESCE(m.name, g.name) AS item_name,
       d.qty, d.unit_cost, d.amount
FROM purchase_order_detail d
LEFT JOIN menu m ON d.menu_id = m.menu_id
LEFT JOIN game g ON d.game_id = g.game_id
WHERE d.po_id = ?;
```

`COALESCE(a, b)`: a가 NULL이면 b. 메뉴면 메뉴 이름, 보드게임이면 게임 이름이 나온다.

**직전 단가 불러오기** (품목을 고르면 단가 칸에 자동 입력, 수정 가능)

```sql
SELECT d.unit_cost
FROM purchase_order_detail d
JOIN purchase_order p ON d.po_id = p.po_id
WHERE d.item_type = '메뉴' AND d.menu_id = ? AND p.status <> '취소'
ORDER BY p.order_date DESC, d.po_detail_id DESC
LIMIT 1;
-- 보드게임이면 item_type = '보드게임' AND d.game_id = ?
-- 결과가 없으면(처음 발주) 단가 칸을 비워 둔다
```

**[입고 처리] — 트랜잭션**

```sql
START TRANSACTION;
UPDATE purchase_order SET status = '입고', receive_date = NOW()
WHERE po_id = 1 AND status = '요청';        -- 1 row → 계속 / 0 rows → 이미 처리됨 → ROLLBACK
SELECT item_type, menu_id, game_id, qty FROM purchase_order_detail WHERE po_id = 1;
UPDATE menu SET stock = stock + 20, sold_out = 0 WHERE menu_id = 2;   -- 오렌지주스 30 → 50
UPDATE menu SET stock = stock + 30, sold_out = 0 WHERE menu_id = 5;   -- 츄러스 0 → 30, 품절 해제
COMMIT;
```

- `AND status = '요청'`: [입고]를 두 번 눌러도 두 번째는 0 rows → 재고가 두 번 늘지 않는다.
- 보드게임 품목은 game 테이블이 ③ 담당이므로 **직접 UPDATE하지 않고** ③의 `GameDAO.increaseStock(con, gameId, qty)`를 같은 Connection으로 호출한다. (③ 안의 SQL: `UPDATE game SET stock = stock + ? WHERE game_id = ?`)
- 하나라도 실패하면 rollback → "상태는 '입고'인데 재고는 그대로"인 상황을 막는다.

```sql
-- 연습: 발주 2(보드게임) 입고. Workbench에서는 ③ 메서드 대신 그 안의 SQL을 직접 실행
START TRANSACTION;
UPDATE purchase_order SET status = '입고', receive_date = NOW()
WHERE po_id = 2 AND status = '요청';
UPDATE game SET stock = stock + 1 WHERE game_id = 6;   -- 카탄 1 → 2
UPDATE game SET stock = stock + 1 WHERE game_id = 1;   -- 스플렌더 2 → 3
COMMIT;
```

**[발주 취소]**

```sql
UPDATE purchase_order SET status = '취소' WHERE po_id = ? AND status = '요청';
-- 이미 입고된 발주는 0 rows → "입고된 발주는 취소할 수 없습니다."

-- 연습: 발주 3 취소
UPDATE purchase_order SET status = '취소' WHERE po_id = 3 AND status = '요청';
```

## 6. 트랜잭션 연습 — 오류가 나면 직접 ROLLBACK

Workbench에서 **한 줄씩**(커서를 줄에 두고 `Ctrl + Enter`) 실행한다.

```sql
START TRANSACTION;
INSERT INTO purchase_order (staff_id, supplier, order_date, total_amount, status)
VALUES (1, '바른식자재', NOW(), 3000, '요청');
SET @po = LAST_INSERT_ID();
INSERT INTO purchase_order_detail (po_id, item_type, menu_id, game_id, qty, unit_cost, amount)
VALUES (@po, '메뉴', 999, NULL, 1, 3000, 3000);     -- 없는 메뉴 → ERROR 1452
SELECT COUNT(*) FROM purchase_order WHERE po_id = @po; -- 1 ← 오류가 나도 헤더는 아직 살아 있다!
ROLLBACK;
SELECT COUNT(*) FROM purchase_order WHERE po_id = @po; -- 0 ← 빈 발주가 남지 않음
```

배울 점:
- **오류가 난다고 앞의 INSERT가 저절로 취소되지 않는다.** 그래서 Java의 `catch`에서 반드시 `con.rollback()`을 부른다.
- rollback한 뒤 다음 발주 번호가 하나 건너뛸 수 있다(예: 4 → 5). AUTO_INCREMENT의 정상 동작이다.

## 7. 잘 만들어졌는지 확인

```sql
SHOW TABLES;                              -- 17개

SELECT p.po_id, p.total_amount, SUM(d.amount) AS detail_sum
FROM purchase_order p
JOIN purchase_order_detail d ON d.po_id = p.po_id
GROUP BY p.po_id, p.total_amount
HAVING p.total_amount <> SUM(d.amount);

SELECT * FROM purchase_order_detail
```

## 8. 자주 나는 오류

| 오류 | 뜻 | 해결 |
|---|---|---|
| `1824` Failed to open the referenced table (MariaDB `1005 errno 150`) | FK가 가리킬 테이블이 아직 없음 | 2번 순서대로 만들기 |
| `1452` Cannot add or update a child row | FK 값이 상대 테이블에 없음 (없는 직원·메뉴 번호) | 번호 확인 |
| `1451` Cannot delete or update a parent row | 다른 테이블이 가리키는 메뉴를 삭제 | 삭제 대신 품절 처리 |
| `1062` Duplicate entry | UNIQUE 중복 (같은 메뉴 이름) | 다른 이름 |
| `1048` Column cannot be null | NOT NULL 칸이 빔 | 입력 검사 |
| `1406` Data too long / `1366` Incorrect string value | 글자 수 초과, 또는 한글 인코딩 문제 | DB를 `utf8mb4`로 만들기(공통 스크립트는 이미 적용), JDBC 주소에 `characterEncoding=UTF-8` |
| `Communications link failure` | MySQL 서버가 꺼져 있음 | Workbench로 접속되는지 먼저 확인 |
| `Access denied for user` | 계정·비밀번호 틀림 | 1-3의 계정, `DBUtil` 값 확인 |
| `No suitable driver` | connector jar가 Build Path에 없음 | 9번 1단계 |

## 9. Java에서 연결 확인 — `DBUtil` (④ 담당, 팀 전원 사용)

1. **jar 추가**: 프로젝트 우클릭 → `Build Path` → `Configure Build Path` → `Libraries` → `Classpath` 선택 → `Add External JARs…` → `mysql-connector-j-8.x.x.jar`
2. **DBUtil** (1-3의 전용 계정 기준)

```java
package dicepos.common;

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.SQLException;

public class DBUtil {
    private static final String URL =
        "jdbc:mysql://localhost:3306/dicepos?serverTimezone=Asia/Seoul&characterEncoding=UTF-8";
    private static final String USER = "dicepos";
    private static final String PASSWORD = "dice1234";

    public static Connection getConnection() throws SQLException {
        return DriverManager.getConnection(URL, USER, PASSWORD);
    }
}
```

3. **연결 테스트** — 실행해서 `연결 성공! 메뉴 7개`가 나오면 끝 (공통 스크립트만 실행한 상태 기준)

```java
package dicepos.common;

import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;

public class DBTest {
    public static void main(String[] args) {
        String sql = "SELECT COUNT(*) FROM menu";
        try (Connection con = DBUtil.getConnection();
             PreparedStatement ps = con.prepareStatement(sql);
             ResultSet rs = ps.executeQuery()) {
            rs.next();
            System.out.println("연결 성공! 메뉴 " + rs.getInt(1) + "개");
        } catch (SQLException e) {
            System.out.println("연결 실패: " + e.getMessage());
        }
    }
}
```

> 11주차에 ④가 팀 전원의 DB 만들기와 이 연결 테스트를 도와준다(개인 개발 문서 일정).
