# DB 만들기 — ④ 박준영

**내 테이블**: `menu`(메뉴) · `purchase_order`(발주) · `purchase_order_detail`(발주 상세)

MySQL Workbench에서 1단계부터 차례로 따라 하면 된다. SQL은 복사해서 실행하면 되고, 결과가 표와 같으면 성공이다.

---

## 1단계. 팀 DB 만들기

1. Workbench에서 `Local instance` 접속
2. `File → Open SQL Script` → [`dicepos_schema.sql`](../dicepos_schema.sql) 열기
3. ⚡ 번개 아이콘 클릭 (전체 실행)
4. 왼쪽 `SCHEMAS`에서 새로고침 → `dicepos` 안에 테이블이 **17개**면 성공

> 이 파일을 다시 실행하면 DB가 **처음 상태로 돌아간다.** 연습하다 꼬이면 다시 실행하면 된다.

## 2단계. 내 테이블 알아보기

공통 스크립트가 이미 만들어 준 테이블이다. 각 줄이 무슨 뜻인지만 이해하면 된다.

```sql
CREATE TABLE menu (
  menu_id   INT          NOT NULL AUTO_INCREMENT,  -- 메뉴 번호 (자동으로 1, 2, 3 …)
  name      VARCHAR(30)  NOT NULL,                 -- 메뉴 이름
  category  VARCHAR(10)  NOT NULL,                 -- 음료 / 간식 / 식사
  price     INT          NOT NULL,                 -- 판매 가격
  stock     INT          NOT NULL DEFAULT 0,       -- 재고 (안 넣으면 0)
  sold_out  TINYINT(1)   NOT NULL DEFAULT 0,       -- 품절이면 1
  PRIMARY KEY (menu_id),
  UNIQUE (name)                                    -- 같은 이름 메뉴는 못 만듦
);

CREATE TABLE purchase_order (                      -- 발주 1건 = 1줄
  po_id         INT          NOT NULL AUTO_INCREMENT,  -- 발주 번호
  staff_id      INT,                                   -- 발주한 직원 (staff 테이블의 번호)
  supplier      VARCHAR(30),                           -- 거래처
  order_date    DATETIME     NOT NULL,                 -- 발주 일시
  total_amount  INT          NOT NULL DEFAULT 0,       -- 총 발주 금액
  status        VARCHAR(10)  NOT NULL DEFAULT '요청',  -- 요청 / 입고 / 취소
  receive_date  DATETIME,                              -- 입고 일시 (입고 전이면 비어 있음)
  PRIMARY KEY (po_id),
  FOREIGN KEY (staff_id) REFERENCES staff(staff_id) ON DELETE SET NULL
);

CREATE TABLE purchase_order_detail (               -- 발주한 품목마다 1줄
  po_detail_id  INT          NOT NULL AUTO_INCREMENT,  -- 상세 번호
  po_id         INT          NOT NULL,                 -- 어느 발주인지 (purchase_order의 번호)
  item_type     VARCHAR(10)  NOT NULL,                 -- '메뉴' 또는 '보드게임'
  menu_id       INT,                                   -- 메뉴면 메뉴 번호
  game_id       INT,                                   -- 보드게임이면 게임 번호
  qty           INT          NOT NULL,                 -- 수량
  unit_cost     INT          NOT NULL,                 -- 사 올 때 단가
  amount        INT          NOT NULL,                 -- 금액 = 수량 × 단가
  PRIMARY KEY (po_detail_id),
  FOREIGN KEY (po_id)   REFERENCES purchase_order(po_id) ON DELETE CASCADE,
  FOREIGN KEY (menu_id) REFERENCES menu(menu_id),
  FOREIGN KEY (game_id) REFERENCES game(game_id)
);
```

**꼭 기억할 4가지**

1. **발주는 테이블 2개.** 발주 1건은 `purchase_order`에 1줄, 품목은 `purchase_order_detail`에 품목마다 1줄. (결제·주문도 같은 방식)
2. **`menu_id`와 `game_id`는 둘 중 하나만 채운다.** 메뉴를 발주하면 `menu_id`, 보드게임이면 `game_id`. 나머지는 비워 둔다(NULL).
3. **`unit_cost`(사 올 때 값)와 `price`(팔 때 값)는 다르다.** 단가는 발주마다 바뀔 수 있어서 상세에 그때 값을 저장한다.
4. **가리키는 테이블이 먼저 있어야 한다.** 발주는 직원(staff)을, 발주 상세는 발주·메뉴·게임을 가리키므로 그 테이블들이 먼저 만들어져 있어야 한다. 공통 스크립트가 이미 이 순서로 되어 있다.

## 3단계. 발주 1건 넣어 보기

오렌지주스 20개와 츄러스 30개를 발주한다. (츄러스는 지금 재고 0, 품절 상태)

```sql
USE dicepos;

START TRANSACTION;                                     -- 여기부터 한 덩어리
INSERT INTO purchase_order (staff_id, supplier, order_date, total_amount, status)
VALUES (1, '바른식자재', NOW(), 69000, '요청');          -- 발주 1건
SET @po = LAST_INSERT_ID();                            -- 방금 생긴 발주 번호를 기억
INSERT INTO purchase_order_detail (po_id, item_type, menu_id, game_id, qty, unit_cost, amount) VALUES
 (@po, '메뉴', 2, NULL, 20, 1200, 24000),              -- 오렌지주스 20개
 (@po, '메뉴', 5, NULL, 30, 1500, 45000);              -- 츄러스 30개
COMMIT;                                                -- 확정
```

> 보드게임이라면 상세 줄이 이렇게 된다: `(@po, '보드게임', NULL, 6, 1, 38000, 38000)` ← 카탄 1개, `menu_id` 자리가 NULL

**확인**

```sql
SELECT * FROM purchase_order;
SELECT * FROM purchase_order_detail;
```

| po_id | staff_id | supplier | total_amount | status |
|---|---|---|---|---|
| 1 | 1 | 바른식자재 | 69000 | 요청 |

| po_detail_id | po_id | item_type | menu_id | game_id | qty | unit_cost | amount |
|---|---|---|---|---|---|---|---|
| 1 | 1 | 메뉴 | 2 | NULL | 20 | 1200 | 24000 |
| 2 | 1 | 메뉴 | 5 | NULL | 30 | 1500 | 45000 |

## 4단계. 메뉴 관리 화면에 쓸 SQL

Java에서는 숫자·글자 자리를 `?`로 바꿔서 쓴다. (예: `WHERE menu_id = ?`)

| 버튼 | SQL |
|---|---|
| 목록 보기 | `SELECT * FROM menu ORDER BY category, name;` |
| [추가] | `INSERT INTO menu (name, category, price, stock) VALUES ('레몬에이드', '음료', 3500, 20);` |
| [수정] | `UPDATE menu SET price = 3800 WHERE menu_id = 8;` |
| 품절 체크 | `UPDATE menu SET sold_out = 1 WHERE menu_id = 8;` |
| [삭제] | `DELETE FROM menu WHERE menu_id = 8;` |

> 오렌지주스(2번)처럼 **발주·주문·결제 기록이 있는 메뉴는 삭제되지 않는다** (오류 1451). 이럴 때는 삭제 대신 품절로 바꾼다.

**⑥ 김하진에게 주는 재고 빼기** (손님이 주문하면 ⑥이 이 기능을 부른다)

```sql
UPDATE menu SET stock = stock - 2 WHERE menu_id = 6 AND stock >= 2;   -- 라면 2개 빼기
```

`AND stock >= 2`: 재고가 모자라면 아무것도 바뀌지 않는다(0 rows). 그래서 재고가 마이너스가 되지 않는다.

## 5단계. 발주 관리 화면에 쓸 SQL

| 버튼 | SQL |
|---|---|
| 발주 목록 | `SELECT * FROM purchase_order ORDER BY order_date DESC;` |
| 발주 상세 | `SELECT * FROM purchase_order_detail WHERE po_id = 1;` |
| 단가 자동 입력 | `SELECT unit_cost FROM purchase_order_detail WHERE menu_id = 2 ORDER BY po_detail_id DESC LIMIT 1;` (가장 최근 단가) |

**[입고 처리]** — 물건이 도착하면 발주 상태를 바꾸고 재고를 늘린다.

```sql
START TRANSACTION;
UPDATE purchase_order SET status = '입고', receive_date = NOW()
WHERE po_id = 1 AND status = '요청';                                  -- 1번 발주를 '입고'로
UPDATE menu SET stock = stock + 20, sold_out = 0 WHERE menu_id = 2;   -- 오렌지주스 +20
UPDATE menu SET stock = stock + 30, sold_out = 0 WHERE menu_id = 5;   -- 츄러스 +30, 품절 풀림
COMMIT;
```

- **트랜잭션으로 묶는 이유**: 상태만 '입고'로 바뀌고 재고는 그대로인 일을 막으려고.
- **보드게임 재고**는 ③ 김은별 담당 테이블이라, 내가 직접 바꾸지 않고 ③이 만든 메서드를 불러서 늘린다.

**확인**

```sql
SELECT name, stock, sold_out FROM menu WHERE menu_id IN (2, 5);
```

| name | stock | sold_out |
|---|---|---|
| 오렌지주스 | 50 | 0 |
| 츄러스 | 30 | 0 |

**[발주 취소]**

```sql
UPDATE purchase_order SET status = '취소' WHERE po_id = 1 AND status = '요청';
```

1번은 이미 입고됐으므로 아무것도 바뀌지 않는다(0 rows). `AND status = '요청'` 덕분에 **입고된 발주는 취소되지 않는다.** 같은 이유로 [입고]를 두 번 눌러도 재고가 두 번 늘지 않는다.

## 6단계. 오류가 나면 되돌리기 (rollback)

없는 메뉴(999번)를 발주해서 일부러 오류를 낸다. Workbench에서 **한 줄씩** 실행한다(줄에 커서를 두고 `Ctrl + Enter`).

```sql
START TRANSACTION;
INSERT INTO purchase_order (staff_id, supplier, order_date, total_amount, status)
VALUES (1, '바른식자재', NOW(), 3000, '요청');
SET @po = LAST_INSERT_ID();
INSERT INTO purchase_order_detail (po_id, item_type, menu_id, game_id, qty, unit_cost, amount)
VALUES (@po, '메뉴', 999, NULL, 1, 3000, 3000);    -- 999번 메뉴는 없음 → 오류 1452
ROLLBACK;                                           -- 위에서 넣은 발주까지 전부 취소
SELECT * FROM purchase_order WHERE po_id = @po;     -- 0줄이면 성공
```

**오류가 나도 앞에서 넣은 발주는 저절로 지워지지 않는다.** 그래서 Java에서도 오류가 나면 꼭 `rollback()`을 부른다.

## 7단계. Java에서 연결 확인

1. Eclipse 프로젝트 우클릭 → `Build Path` → `Configure Build Path` → `Libraries` → `Add External JARs…` → `mysql-connector-j` jar 선택
2. 아래 두 파일을 만들고 `DBTest`를 실행 → **`연결 성공! 메뉴 7개`** 가 나오면 성공 (1단계 직후 기준)

```java
package dicepos.common;

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.SQLException;

public class DBUtil {
    private static final String URL =
        "jdbc:mysql://localhost:3306/dicepos?serverTimezone=Asia/Seoul&characterEncoding=UTF-8";
    private static final String USER = "root";
    private static final String PASSWORD = "본인 root 비밀번호";

    public static Connection getConnection() throws SQLException {
        return DriverManager.getConnection(URL, USER, PASSWORD);
    }
}
```

```java
package dicepos.common;

import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;

public class DBTest {
    public static void main(String[] args) {
        try (Connection con = DBUtil.getConnection();
             PreparedStatement ps = con.prepareStatement("SELECT COUNT(*) FROM menu");
             ResultSet rs = ps.executeQuery()) {
            rs.next();
            System.out.println("연결 성공! 메뉴 " + rs.getInt(1) + "개");
        } catch (SQLException e) {
            System.out.println("연결 실패: " + e.getMessage());
        }
    }
}
```

> `DBUtil`은 ④가 만들어 팀 전원이 쓴다. 비밀번호가 사람마다 다르면 팀원마다 이 줄을 고쳐야 하니, 팀 공용 DB 계정을 만들지 회의에서 정한다.

## 자주 나는 오류

| 오류 | 이유 | 해결 |
|---|---|---|
| 1452 | 없는 번호를 넣음 (없는 메뉴·직원) | 번호 확인 |
| 1451 | 기록이 있는 메뉴를 삭제 | 품절로 바꾸기 |
| 1062 | 같은 이름의 메뉴가 이미 있음 | 다른 이름 |
| 1048 | 꼭 넣어야 하는 칸이 비었음 | 빈칸 채우기 |
| Communications link failure | MySQL이 꺼져 있음 | Workbench로 접속되는지 확인 |
| Access denied | 아이디·비밀번호 틀림 | `DBUtil` 값 확인 |
